# 0.0.6 自动登录拦截设计

更新日期：2026-09-15。

## 已实现

1. 新增 `src/login-guard.ts`。在页面窗口上同步监听 `csdn`、`loginBox` 和 `show / key / showTip / showAutoTip` 的普通赋值；覆盖延迟加载、整个组件替换和方法替换，不使用持续轮询。
2. 四种入口默认拒绝无手动授权的调用，因此滚动、计时、阅读次数、复制及其他经过这些入口的触发均受到拦截。带 `reportExtra.autoPopup` 的调用始终拒绝。
3. document 捕获阶段识别真实 click 的可点击元素文字、title、aria-label；登录或注册入口授予 1500ms 的一次性授权。普通点击撤销授权，合成点击无法授权；浏览器键盘激活按钮产生的 click 使用同一流程。
4. 手动授权调用保留 this、参数、回调、返回值及异常，关闭和登录状态接口不变，不统一隐藏登录容器或阻断网页全部滚动事件。
5. userscript 使用 `document-start` 和 `unsafeWindow`，原有文章增强等待 load，避免提前运行导致正文不存在。版本更新为 0.0.6。

## 验证与限制

- `node src/login-guard.test.mjs` 验证实际拦截器的四个入口、一次性授权、过期、伪造点击、自动标记、延迟加载和替换；属于隔离模拟，不是浏览器验收。
- `pnpm dlx pnpm@8.15.9 run build` 验证 TypeScript 和产物。
- 原有 `src/audit-current.mjs` 已适配模块入口，继续报告现存三个旧缺陷，不将它的成功退出误解为功能正常。
- 不改写已有 getter/setter 或不可配置属性；网站用 defineProperty/delete 重定义访问器、新增独立弹窗组件、脚本注入晚于网页脚本时，可能需要适配。
- 无名称图标或超过 1500ms 的手动异步登录可能被拒绝。短授权窗口内恰好出现的无自动标记调用可能消耗授权；本次实现不能完全判别任意异步调用的因果关系。
- 未清除用户浏览器 Cookie，未完成真实油猴安装及匿名浏览器交互验收。仍需在 docs/TEST.md 中的页面验证滚动、停留、切换可见性、复制、手动登录和关闭后再次登录。
